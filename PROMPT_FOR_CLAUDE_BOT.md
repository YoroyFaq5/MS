# Промпт для Claude: Telegram-бот MafiaTracker 2.0

Работай сразу с двумя соседними репозиториями:

- `C:\0_Projects\MS` — основной Flask-сайт и источник бизнес-логики/данных;
- `C:\0_Projects\MS-TG` — отдельный Telegram-бот на Flask + pyTelegramBotAPI.

Цель: превратить бота в красивый, быстрый и максимально полный Telegram-клиент сайта. Обычный пользователь должен пользоваться ботом почти полностью кнопками, без необходимости помнить или печатать команды. Используй возможности Telegram: inline-клавиатуры, редактирование существующих сообщений, callback query, изображения/медиа там, где они действительно улучшают интерфейс, deep links, inline mode, Web App только для сценариев, которые невозможно удобно выразить обычными кнопками.

Не ограничивайся планом: исследуй оба проекта, реализуй изменения, добавь миграции при необходимости, тесты и документацию, затем запусти проверки. Не делай коммит. Не перезаписывай существующие незакоммиченные изменения.

## 1. Принципы интерфейса

- `/start` остаётся единственной обязательной текстовой командой и открывает главное меню.
- Все основные сценарии доступны через кнопки. Текстовые команды можно оставить как скрытые совместимые shortcuts, но пользовательский интерфейс не должен требовать их знания.
- Основную навигацию построй на inline-клавиатурах и редактировании одного сообщения, чтобы чат не превращался в поток одноразовых меню.
- В каждом разделе должны быть понятные кнопки `← Назад`, `🏠 Главное меню` и контекстное обновление `🔄 Обновить`.
- Не смешивай Reply Keyboard и Inline Keyboard бессистемно. Оставь компактную постоянную Reply Keyboard только как быстрый вход в главное меню либо полностью перейди на inline-меню, если это надёжнее.
- Callback data должна быть версионированной, короткой и укладываться в лимит Telegram 64 байта. Не помещай туда доверенные цены, права, баланс или другие бизнес-данные — только действие и идентификаторы; всё важное повторно проверяет сайт.
- Всегда отвечай на callback query, включая ошибки, чтобы в Telegram не зависал индикатор загрузки.
- Для операций с деньгами, покупок, подарков, отвязки аккаунта и других значимых действий показывай экран подтверждения с итогом операции.
- Добавь защиту от двойного нажатия и повторной обработки одного callback/update.
- Все сообщения должны корректно экранироваться для HTML parse mode. Данные игрока, название турнира, товара, заметка к подарку и любые данные API нельзя вставлять как готовый HTML.
- Длинные списки выводи с пагинацией. Сохраняй пользователя на той же странице после действия, если это логично.
- При устаревшей кнопке, удалённом объекте или изменившемся статусе показывай дружелюбное сообщение и кнопку возврата, а не техническую ошибку.
- Сохрани доступность: не полагайся только на цвет/эмодзи, добавляй текстовые подписи и не делай чрезмерно плотные клавиатуры.

## 2. Новая структура главного меню

Сделай кнопочное главное меню примерно из следующих разделов:

1. `👤 Мой кабинет` — профиль, статистика, история игр, достижения, титулы, оформление, аккаунт.
2. `🏆 Рейтинги` — общий, текущий сезон, сезоны года, годовой рейтинг, моё место.
3. `🎮 Турниры` — активные, будущие, завершённые, обычные и серийные турниры.
4. `🎯 Fantasy` — доступные драфты, мои драфты, история, лидерборды, обычный/тренировочный режим.
5. `🛍 Магазин` — каталог, категории, карточка товара, покупка.
6. `🎒 Инвентарь` — предметы, экипировать/снять, активное оформление.
7. `🎁 Подарки` — входящие, отправить подарок, история.
8. `🆚 Сравнить игроков` — кнопочный поиск и inline mode.
9. `🔔 Уведомления` — пользовательские настройки типов уведомлений.

Сделай экраны визуально единообразными: короткий заголовок, 2–6 ключевых показателей, затем действия. Не пытайся копировать HTML сайта в Telegram. Создай небольшую дизайн-систему presenters: заголовки, карточки, строки статистики, пагинация, состояния empty/error/loading и клавиатуры.

## 3. Максимальное покрытие пользовательских функций сайта

Сначала составь фактическую матрицу `функция сайта → endpoint Bot API → экран/действие бота → тест`. Затем реализуй отсутствующее.

Обязательно добавь:

### Сезоны и рейтинги

- текущий сезон, календарь сезонов, детальная таблица сезона и годовой рейтинг;
- карточку `Моё место` с количеством игр, порогом участия в топ-5, очками, GG и ближайшими соперниками;
- историю победителей и переход в профиль игрока кнопкой;
- корректное объяснение нового правила: места 1–5 доступны после 8 игр.

### Обычные и серийные турниры

- единый список с фильтрами по статусу и типу;
- детали турнира, участники, этапы, игры и лидерборд;
- серийные турниры, конкретные игровые вечера, состав вечера и рейтинг серии;
- пользовательские ссылки должны вести в правильный серийный контекст;
- строго соблюдай `hide_standings`: Bot API сейчас выдаёт `player_ratings` без эквивалентной проверки. Закрой эту утечку на стороне сайта и протестируй.

### Fantasy

- не только обычный `tournament_id`, но и `tournament_series_id`, `group_number`, `is_practice`;
- список доступных Fantasy-событий без необходимости вводить ID турнира;
- создание драфта, добавление/удаление пиков, просмотр состава, лимита и стоимости;
- история всех драфтов и лидерборды с пагинацией;
- перед платным драфтом — подтверждение стоимости и актуального баланса;
- отображение заблокированного/подсчитанного состояния и результата.

### Магазин и инвентарь

- категории и фильтры магазина, карточка товара, цена, редкость, наличие и состояние `уже куплено`;
- покупка только после подтверждения, с повторной серверной проверкой цены и баланса;
- инвентарь, экипировка и снятие предметов;
- отображение активного ника/рамки/оформления там, где Telegram позволяет это показать безопасно и понятно;
- недоступные физические или админские операции оставляй ссылкой на сайт.

### Подарки

- входящие подарки, история, выбор получателя через поиск;
- выбор только доступного подарка из инвентаря;
- необязательная заметка через короткий FSM-сценарий с кнопкой отмены;
- финальное подтверждение получателя и предмета;
- защита от подарка самому себе и повторной отправки.

### Профиль, достижения и титулы

- удобный личный кабинет, подробная статистика и история игр;
- страницы достижений с категориями, прогрессом и пагинацией;
- закрепление/открепление достижений;
- просмотр, экипировка и снятие титула;
- сравнение игроков без ручного ввода ID: поиск по имени, недавние соперники и inline mode.

### Карточка игры

- результат, дата, состав, роли, очки, бонусы и ссылка на турнир/серию;
- переход к карточке из истории, турнира и уведомления;
- учитывай скрытые или административные поля: обычному пользователю не раскрывать то, чего нет в публичном UI сайта.

## 4. Уведомления

Сохрани существующие события и добавь пользовательские настройки по категориям:

- моя следующая рассадка;
- начало/изменение турнира или вечера серии;
- завершение моей игры;
- изменение рейтинга/места сезона;
- достижение или титул;
- Fantasy: блокировка, результат, приз;
- подарок;
- покупка/перекуп предмета;
- сезонная награда и квалификация в «Стол года».

У каждого уведомления должны быть контекстные кнопки: `Открыть игру`, `Турнир`, `Fantasy`, `Профиль`, `Настроить уведомления`. Не присылай уведомление самому инициатору там, где оно не несёт пользы.

## 5. Надёжность доставки

Текущий `BotNotifyService` делает синхронный HTTP POST с таймаутом до 8 секунд и без очереди. Измени архитектуру так, чтобы недоступность бота не задерживала основной пользовательский сценарий и события не терялись.

Предпочтительная схема:

- transactional outbox на стороне `MS`: событие записывается в БД вместе с бизнес-операцией;
- отдельный worker доставляет события на `MS-TG` с ограниченными повторами и exponential backoff;
- у события есть уникальный `event_id`, тип, payload, время, число попыток и статус;
- `MS-TG` обеспечивает идемпотентность по `event_id`, чтобы повтор не породил двойное сообщение;
- endpoint бота быстро принимает событие и не блокируется на длительной работе;
- должны быть наблюдаемость и безопасная ручная повторная отправка неудавшегося события.

Если полная очередь слишком велика для одного инкремента, реализуй безопасный минимальный outbox и явно опиши следующий шаг. Не используй fire-and-forget thread внутри WSGI-процесса как гарантию доставки.

## 6. Безопасность Bot API

- Сохрани server-to-server авторизацию, но сравнивай секреты константным сравнением.
- Не считай один service token достаточным доказательством действий конкретного пользователя. Каждый mutating endpoint должен резолвить `telegram_id`, проверять владельца ресурса и права на стороне сайта.
- Добавь rate limiting для Bot API и входящих webhook endpoint’ов.
- Ограничь размер JSON body и валидируй типы/диапазоны параметров.
- Не возвращай приватные или скрытые данные через Bot API.
- Не логируй токены, подписи, полные webhook URL и персональные payload’ы.
- Поддержи ротацию секретов без длительного простоя, если это разумно для текущей архитектуры.
- Проверь Telegram webhook secret header и HMAC через `compare_digest`.

## 7. Deep links и Telegram Web App

- Добавь deep links для открытия конкретного турнира, игры, Fantasy-драфта, подарка или профиля после `/start`.
- Ссылки из сайта на бота должны открывать нужный экран, а не только главное меню.
- Web App используй только для действительно сложных визуальных сценариев: массовый выбор Fantasy, большая таблица или кастомизация профиля. Основные операции обязаны оставаться доступными обычными inline-кнопками.
- Если добавляешь Web App, проверяй `initData` на сервере и не доверяй данным клиента.

## 8. Архитектура и качество кода

- Сохрани разделение `handlers → services → api_client → MS API` и чистые presenters.
- Не дублируй бизнес-правила сайта в боте. Цены, права, доступность, лимиты и статусы определяет `MS`.
- Для многошаговых сценариев введи минимальное устойчивое состояние/FSM. Состояние не должно безвозвратно теряться при рестарте процесса; выбери Redis или небольшую БД и объясни выбор.
- Не держи всю навигацию в одном огромном handler-файле. Разделяй по доменам.
- Добавь централизованный обработчик ошибок API и Telegram, correlation/request ID и структурированные логи.
- Обнови устаревшие README/ARCHITECTURE: сейчас документация утверждает, что вся полировка завершена, хотя покрытие сайта неполное.

## 9. Тесты и критерии приёмки

Добавь тесты как минимум на:

1. Все главные пользовательские сценарии проходят от кнопки до API и обратно без текстовых команд.
2. У каждого вложенного экрана есть корректный `Назад` и `Главное меню`.
3. Callback data не превышает 64 байта и не содержит доверенных бизнес-данных.
4. Пользовательский текст безопасно экранируется в HTML parse mode.
5. Двойное нажатие не создаёт две покупки, два подарка или два платных драфта.
6. Скрытый рейтинг турнира нельзя получить через Bot API.
7. Пользователь не может изменить чужой драфт, инвентарь, титул или настройки.
8. Fantasy поддерживает обычные турниры, серии, группы и practice mode.
9. Outbox повторяет доставку и бот дедуплицирует повтор по `event_id`.
10. Устаревшие кнопки и удалённые сущности обрабатываются без traceback.
11. Пагинация корректна на первой, средней и последней странице.
12. Deep link открывает ожидаемый экран после `/start`.

Запусти тесты обоих репозиториев и статические проверки. Не ухудшай существующее покрытие.

9. полная проверка, документация и итоговый отчёт.
